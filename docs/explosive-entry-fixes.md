# 爆发行情捕获但未开仓修复

## 排查结果

2026-11-12 云端近 24 小时的 19 条消费记录中，10 条试探信号仅观察，
2 条回踩信号因没有底仓被拒绝，2 条因合约 K 线过期被拒绝，5 条为无仓位的失效通知。
另发现 V2 开多同步分单位错误：特征范围为 0–1，执行却要求至少 65。

## 本次变更

1. V2 同步分统一为 0–1，开多要求 0.65–1.0；拒绝错误的百分制输入。
2. V2 不再依赖旧扫描器的 `explosive_breakout_pending` 缓存状态，使用最新且有效的
   V2 特征和实时收盘突破确认作为执行依据，避免两套阈值重复否决。
3. 没有底仓的回踩信号可以作为首次入场候选，仍通过完整确认、止损结构和账户风控；
   仓位不超过确认入场上限，不使用回踩加仓的较大上限。有底仓加仓仍要求盈利。
4. 暂时缺少或过期的数据进入 `WAITING_DATA`，至少间隔 30 秒重试。
   只重试未下单的事件，原子领取防止重复；过期或同一 setup 已失效的信号不再执行。
   执行前的数据检查若阻断下单，也进入等待。订单结果不明或实际下单失败不自动重发。
5. 放量观察、过热/OI 异常、实际开仓结果使用不同提醒标题。
   风险提醒不再显示“做多”；V2 开仓结果接入提醒，通知字段不改变执行风控路径。

## 保留的约束

- 早期 `PROBE_LONG` 仍只观察，不能将观察提醒当作可执行入场。
- 开多仍要求评分至少 80、现货和合约 15m 量比至少 1.5、同步分至少 0.65、
  15m 涨幅至少 0.5%、1h 涨幅至少 1%、OI 1h 至少 +0.5% 或 4h 至少 +1%，
  以及突破后下一根完整 15m K 线确认。
- 保留合约可交易性、账户开关、止损、仓位和风险预算、盘口及组合风险检查。
- 不重放已经终结的历史拒绝事件；不保证每次捕获都会开仓或盈利。

数据恢复重试、重复领取防护、信号过期和结构失效，以及提醒分类。
全量回归 588 项通过；最终针对性回归 29 项通过。
